## [cite_start]2. Resumen Ejecutivo [cite: 27]
[cite_start]El proyecto "M.U.M.N.K8s" tiene como propósito aplicar los conocimientos adquiridos en las unidades 1 y 2 del curso, enfocándose en la implementación de una arquitectura de sistema distribuido y escalable en Google Cloud Platform (GCP) utilizando Google Kubernetes Engine (GKE). [cite: 28] [cite_start]Se construirá un sistema que simula la recepción y procesamiento de reportes militares generados en tiempo real por distintos países. [cite: 29] [cite_start]Cada reporte representará el estado parcial de recursos bélicos, incluyendo la cantidad de aviones de guerra en el aire y barcos de guerra en el mar, junto con su país de origen y marca de tiempo. [cite: 30] 

[cite_start]Este sistema involucrará la generación de tráfico con Locust, una API REST en Rust, servicios en Go para procesamiento y comunicación gRPC, RabbitMQ como sistema de mensajería, consumidores para procesar los mensajes, y bases de datos/servicios de visualización desplegados sobre máquinas virtuales administradas con KubeVirt dentro del clúster. [cite: 31] [cite_start]En particular, Valkey y Grafana deberán ejecutarse en máquinas virtuales independientes sobre KubeVirt. [cite: 32] [cite_start]Todas las imágenes Docker de los componentes deberán publicarse y consumirse desde Zot, desplegado en una máquina virtual de GCP fuera del clúster. [cite: 33] 

[cite_start]El proyecto busca demostrar la comprensión y aplicación de tecnologías de contenedores, orquestación, virtualización dentro de Kubernetes, comunicación entre microservicios, manejo de concurrencia, visualización de métricas y pruebas de carga, así como la integración opcional de Dapr como mecanismo alternativo para el envío de mensajes. [cite: 34]

## [cite_start]3. Enunciado del Proyecto [cite: 36]
[cite_start]En la actualidad, los sistemas distribuidos deben ser capaces de procesar grandes volúmenes de eventos en tiempo real, garantizar escalabilidad, tolerancia a fallos y observabilidad, y además integrarse con distintos mecanismos de comunicación y almacenamiento. [cite: 37] [cite_start]En este proyecto se simulará un escenario de monitoreo bélico donde continuamente se generan reportes militares desde distintos países. [cite: 38] [cite_start]Cada evento contendrá información resumida sobre unidades estratégicas, por ejemplo: país, cantidad de aviones de guerra en el aire, cantidad de barcos de guerra en el mar y una marca de tiempo. [cite: 39] 

[cite_start]El desafío consiste en diseñar e implementar una arquitectura distribuida, escalable y resiliente que permita recibir, procesar, enrutar, consumir, almacenar y visualizar dichos datos utilizando tecnologías modernas de nube, contenedores y virtualización. [cite: 40] [cite_start]La solución deberá ejecutarse en GCP utilizando instancias N1, un clúster de GKE, Kubernetes Gateway API para exponer el sistema, una API REST en Rust, servicios gRPC en Go, RabbitMQ como broker principal de mensajería, Valkey desplegado dentro de una máquina virtual en KubeVirt, y Grafana desplegado en otra máquina virtual independiente también en KubeVirt. [cite: 41] [cite_start]Adicionalmente, el estudiante podrá implementar un flujo alternativo de mensajería utilizando Dapr como parte extra del proyecto. [cite: 42]

### [cite_start]4.3.1 Estructura de los mensajes: [cite: 148]
La estructura de los mensajes deberá representar reportes militares simulados. [cite_start]Un ejemplo de JSON válido es el siguiente: [cite: 149]

```json
{
    "country": "ESP",
    "warplanes_in_air": 42,
    "warships_in_water": 14,
    "timestamp": "2026-03-12T20:15:30Z"
}
```
[cite_start]*[cite: 150, 151, 152, 153, 154, 155]*

[cite_start]**Reglas de generación:** [cite: 156]
* [cite_start]**country:** código de país de 3 letras. [cite: 157]
* [cite_start]**warplanes_in_air:** número entero aleatorio dentro de un rango definido. [cite: 158]
* [cite_start]**warships_in_water:** número entero aleatorio dentro de un rango definido. [cite: 159]
* [cite_start]**timestamp:** fecha y hora del evento. [cite: 160]

[cite_start]**Rangos sugeridos:** [cite: 161]
* [cite_start]**warplanes_in_air:** entre 0 y 50 [cite: 162]
* [cite_start]**warships_in_water:** entre 0 y 30 [cite: 163]

#### [cite_start]Propuesta de estructura gRPC [cite: 165]
```protobuf
syntax = "proto3";
package wartweets;
option go_package = "./proto";

// Mensaje que se enviará
message WarReportRequest {
    Countries country = 1;
    int32 warplanes_in_air = 2;
    int32 warships_in_water = 3;
    string timestamp = 4;
}

// Lista de los únicos posibles países aceptados por el proyecto
enum Countries {
    countries_unknown = 0;
    usa = 1;
    rus = 2;
    chn = 3;
    esp = 4;
    gtm = 5;
}

// Respuesta del servidor
message WarReportResponse {
    string status = 1;
}

// Servicio gRPC
service WarReportService {
    rpc SendReport (WarReportRequest) returns (WarReportResponse);
}
```
